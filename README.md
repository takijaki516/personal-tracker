# 운동관리 — Android + macOS

혼자 사용하는 식단·운동 기록 앱입니다. Android와 Mac에 각각 SQLite로 저장하고, 같은 Wi-Fi에서 두 앱이 암호화된 JSON 데이터를 직접 주고받습니다. Supabase, 클라우드 계정, 로그인은 사용하지 않습니다.

- Android: Expo SDK 57 / React Native 0.86
- macOS: 기존 React Native Web 화면을 사용하는 Electron 설치 앱
- 브라우저: 개발 미리보기용. 기존 localStorage를 유지하며 SQLite·자동 백업·LAN 동기화는 제공하지 않습니다.
- 공통: React 19 / TypeScript strict / Oxlint / Oxfmt / Vitest

처음 기여한다면 [개발 안내](CONTRIBUTING.md)에서 코드 읽는 순서, 플랫폼별 역할, 코드 품질 기준을 확인하세요.

화면 하단의 **Home · 식단 · 운동** 탭으로 기록 화면을 전환합니다. **Home**은 하루 섭취량 요약·운동 기록과 설치 앱의 백업·동기화 영역을 함께 보여주고, **식단**은 영양 요약과 식사별 식단 기록만, **운동**은 운동 기록만 보여줍니다. Home의 식단 카드에는 하루 섭취량 요약을 조회 전용으로 표시합니다. 식단·목표 편집과 식사별 음식 목록은 **식단** 탭에서 사용할 수 있습니다. 상단 날짜 선택 영역과 하단 탭은 목록을 스크롤해도 고정되어 있으며, 탭을 바꿔도 선택한 날짜를 유지합니다. 기록 편집을 마치면 열었던 탭과 스크롤 위치로 돌아옵니다.

식단은 총 칼로리(kcal), 탄수화물(g), 단백질(g), 지방(g)을 기록합니다. 영양소는 선택 입력이며, 기존 칼로리만 있는 기록은 영양소를 미입력으로 표시합니다. 현재 섭취량에 해당하는 영양값을 직접 입력·수정할 수 있으며, 총 영양값을 저장·백업·동기화에 포함합니다.

기록 화면의 식단은 **아침·점심·저녁·간식** 구역으로 나눕니다. 구역 제목에는 **아침 (총: 500 kcal, 탄: 60 g, 단: 30 g, 지: 15 g)** 형식으로 해당 식사의 영양 합계를 항상 표시합니다. 영양소를 모두 입력하지 않은 경우 **미입력**, 일부만 입력한 경우 입력된 값의 합계와 미입력 개수를 표시하며, 기록이 없는 구역의 합계는 0입니다. 각 구역은 기본으로 접혀 있으며 음식 목록에는 이름과 섭취량만 표시합니다. 구역 제목을 누르면 음식별 칼로리·영양소와 **수정·삭제** 버튼을 펼치거나 접을 수 있습니다. 구역은 각각 독립적으로 열 수 있으며, 다른 날짜로 이동하면 다시 접힙니다. 기록이 없는 구역에는 **기록이 없습니다.**를 표시하고, 섭취량 정보가 없는 기존 식단은 **1회분**으로 표시합니다.

식단 입력에서는 **섭취량**만 조절하며, 계산에 사용하는 기준량은 내부에 보관하고 화면에는 표시하지 않습니다. 섭취량을 바꾸면 **총 영양정보**와 칼로리·탄수화물·단백질·지방 입력칸이 함께 조정됩니다. 예를 들어 100g에 165kcal인 음식을 200g 먹으면 총 330kcal로 저장됩니다. 영양값을 직접 수정하면 현재 섭취량에 해당하는 총값으로 적용하며, 이후 양 변경에도 그 값을 사용합니다. FatSecret에 g 정보가 있으면 그램을 사용하고, 없으면 제공량을 1회분으로 사용합니다. 양 정보가 없는 기존 식단·즐겨찾기도 기존 영양값을 1회분으로 유지합니다. **g / 회분** 단위를 바꾸면 영양값은 유지하고 섭취량을 비웁니다. 변경한 단위로 현재 식단의 양을 입력하면 이후 양 변경에 맞춰 자동 계산합니다. 미입력 영양소는 자동 계산 후에도 미입력으로 유지합니다. 비율에 따라 환산한 값은 소수 둘째 자리까지 반올림하며, 내부 기준 영양값을 보관해 반복 변경 시 오차가 누적되지 않도록 합니다. 식단·즐겨찾기·최근 음식에는 섭취량과 내부 기준 정보를 함께 유지하고 저장·백업·복원·동기화에 포함합니다. 양 정보를 동기화하려면 양쪽 앱을 이 기능이 포함된 버전으로 업데이트하세요.

기록 화면의 **식단 → 하루 섭취량 → 목표 설정**에서 하루 목표 섭취 칼로리(kcal), 탄수화물(g), 단백질(g), 지방(g)을 각각 설정할 수 있습니다. 목표는 모든 날짜에 공통으로 적용하며, 설정하지 않을 항목은 비워두세요. **목표 수정**에서 값을 지우고 저장하면 해당 목표를 해제합니다. 식단 카드 안에서 음식 목록 바로 위에 선택한 날짜의 식단 합계와 목표 대비 남은 양·초과량을 표시합니다. 영양소가 미입력된 식단은 합계에 포함하지 않고 미입력 개수를 표시합니다. 칼로리 목표와 영양소 목표는 독립적으로 저장하며 자동 환산하지 않습니다. 목표는 브라우저에서는 localStorage, 설치 앱에서는 SQLite에 저장하고 JSON 백업·복원·기기 동기화에 포함합니다. 목표를 동기화하려면 양쪽 앱을 이 기능이 포함된 버전으로 업데이트하세요.

**식단** 탭의 **식단 수정** 버튼과 음식별 **수정** 버튼은 별도 입력 화면으로 이동합니다. 상단에 **뒤로** 버튼과 기록 날짜를 표시하며, 저장에 성공하거나 취소·뒤로 버튼을 누르면 원래 날짜와 스크롤 위치로 돌아옵니다. 저장에 실패하면 입력값과 오류를 해당 화면에 유지합니다. 입력 중에는 기록 목록을 숨기고 기존 화면 상태를 보존합니다. 운동 입력은 팝업으로 표시합니다.

**식단** 탭에서 여는 **식단 수정** 화면은 선택한 날짜에 기록한 음식들을 기존 식사 구역에 불러옵니다. 음식 이름·섭취량·영양정보를 수정할 수 있으며, **아침·점심·저녁·간식**을 각각 접고 펼칠 수 있습니다. 구역 제목에는 음식 개수와 해당 식사의 **총·탄·단·지** 합계를 표시하며, 접힌 구역에서도 각 음식의 이름·섭취량·총 영양정보를 보여줍니다. 섭취량·영양값을 바꾸거나 음식을 추가·삭제하면 합계가 바로 갱신됩니다. 미입력 영양소는 **미입력**, 계산할 수 없는 음식은 **—**로 표시하며 합계에서 제외합니다. 일부 값이 빠진 합계에는 미입력 음식 개수를 함께 표시합니다. 구역을 펼친 뒤 **음식 추가**를 누르면 해당 식사에 새 입력칸이 생기며, 접었다 다시 열어도 입력값을 유지합니다. 각 구역의 마지막 음식도 삭제할 수 있습니다. **기록 저장**을 누르면 기존 음식의 수정·삭제와 새 음식의 추가를 한 번에 반영합니다. 삭제한 음식은 저장할 때 기록에서 제거되며, 취소·뒤로 버튼으로 나가면 저장된 식단을 유지합니다. 모든 기존 음식을 삭제한 경우에도 빈 식단을 저장할 수 있습니다. 처음부터 기록이 없고 입력한 음식도 없을 때는 저장 버튼을 비활성화합니다. 잘못된 입력이 있으면 해당 구역을 펼치고 식사 시간·음식 번호와 오류를 표시하며 전체 저장을 중단합니다. 저장에 실패하면 입력값을 유지해 다시 시도할 수 있습니다.

아침·점심·저녁·간식에 여러 음식을 한 번에 기록할 수 있습니다. **음식 선택** 화면에서 즐겨찾기·최근 음식·FatSecret 검색 결과를 여러 개 체크하고 **선택 완료**를 누르면 열었던 식사 구역에 음식별 입력칸이 생깁니다. 검색어를 바꿔도 선택한 음식은 유지되며, 다시 누르거나 선택한 음식의 **×** 버튼을 누르면 선택을 해제합니다. 음식별 섭취량과 영양정보를 조절한 뒤 **기록 저장**을 누르면 한 번에 저장합니다. 음식별 **수정** 화면에서는 식사 시간을 선택해 기존 기록과 추가 음식을 함께 저장할 수 있습니다. 각 음식은 개별 식단 기록으로 저장하므로 기존 기록·백업 형식을 유지하며, 기록 목록에서 각각 수정·삭제할 수 있습니다.

식단 입력 화면의 **즐겨찾는 음식** 버튼을 누르면 등록한 음식 목록이 열립니다. 음식 이름과 칼로리·영양소를 입력한 뒤 **즐겨찾기 등록**을 눌러 등록하고, 목록에서 음식을 선택하면 입력칸이 채워집니다. 선택한 식사 시간은 유지되며 **기록 저장**을 눌러야 해당 날짜에 기록됩니다. 같은 이름은 **즐겨찾기 업데이트**로 값을 바꾸고, 목록의 **해제**로 즐겨찾기만 삭제할 수 있습니다. 즐겨찾기는 앱 재실행·JSON 백업·복원·기기 동기화에도 유지됩니다. 즐겨찾기를 동기화하려면 양쪽 앱을 이 기능이 포함된 버전으로 업데이트하세요.

**음식 이름** 입력칸에 포커스하면 별도 **음식 선택** 화면으로 이동합니다. 상단에 뒤로 버튼·기록 날짜·검색 입력칸을 표시하고, **즐겨찾기**와 **최근 음식** 섹션을 입력한 글자로 바로 필터링합니다. 공백과 영문 대소문자는 검색에 영향을 주지 않습니다. 즐겨찾기는 이름순으로, 최근 음식은 식단 날짜가 최신인 순서로 최대 10개를 표시합니다. 같은 날짜에는 나중에 추가한 기록을 먼저 사용하고, 같은 이름은 한 번만 표시합니다. 즐겨찾기에 있는 음식은 최근 음식 목록에서 제외합니다. 음식을 체크한 뒤 **선택 완료**를 누르면 식단 입력 화면으로 돌아와 이름·칼로리·영양소가 채워지고, 기존 식사 시간은 유지됩니다. 처음 선택한 음식은 열었던 입력칸에 적용하고, 추가로 선택한 음식은 그 뒤에 새 입력칸을 만듭니다. 아무 음식도 체크하지 않은 상태에서 **선택 완료**를 누르면 직접 입력한 이름만 적용하고 기존 영양값은 유지합니다. 뒤로가기는 검색과 선택을 취소하고 이전 입력값을 유지합니다. 돌아올 때 식단 입력 화면의 스크롤 위치도 복원합니다. 즐겨찾기·최근 음식 자동완성은 기기에 저장한 데이터만 사용하므로 인터넷 연결이 필요하지 않습니다.

`localhost:8081` 웹 미리보기에서는 음식 선택 화면에 **FatSecret 검색** 영역도 표시합니다. 음식 이름을 한 글자 이상 입력하고 400ms 동안 입력이 없으면 한국 음식·브랜드 제품을 최대 10개 자동 조회합니다. 한글 조합 중에는 조회하지 않으며, 즐겨찾기·최근 음식은 바로 필터링합니다. 결과의 제공량·칼로리·영양소를 확인한 뒤 선택하면 이름(브랜드 포함)과 기준 영양값이 채워집니다. **섭취량**을 바꾸면 실제 섭취한 칼로리·영양소를 자동 계산합니다. 제공되지 않은 영양소는 빈칸으로 유지합니다. 검색에는 인터넷 연결이 필요하며 **기록 저장** 또는 **즐겨찾기 등록**을 눌러야 저장됩니다. 검색어를 바꾸거나 음식 선택 화면을 나가면 진행 중인 조회를 HTML 요청까지 취소하고, 이전 응답은 표시하지 않습니다. 같은 검색어의 성공 결과(결과 없음 포함)는 5분간 최대 30개까지 메모리에 캐시하며 새로고침하면 지워집니다. 실패한 조회는 캐시하지 않으며 **다시 시도**로 재조회할 수 있습니다. Android·Electron 설치 앱에는 외부 음식 검색을 아직 연결하지 않았습니다.

## 개발 환경 및 실행

Node 24.3 이상, 25 미만이 필요합니다.

```sh
nvm install
nvm use
npm ci

npm run mac             # 웹 자산 빌드 후 Mac 앱 실행
npm run build:mac       # release/에 Mac .app 및 .dmg 생성
npm run android:native  # Android 네이티브 개발 앱 빌드·실행
npm run build:apk       # Android release 변형 빌드·실행
```

Android 네이티브 빌드에는 Android Studio/SDK, JDK, 연결 기기 또는 에뮬레이터가 필요합니다. `build:apk`의 APK는 생성된 android/app/build/outputs/apk/release/에서 확인합니다. Expo 기본 release 서명은 개발 키일 수 있으므로 개인 설치용으로 사용하고, 업데이트 시 같은 키를 유지하세요. 스토어 배포 서명은 구성하지 않았습니다.

macOS 빌드는 현재 Mac의 CPU 아키텍처를 대상으로 합니다. 개인용 로컬(ad-hoc) 서명으로 패키징합니다. Apple Developer 인증서와 공증은 사용하지 않습니다. 외부 배포 시 서명·공증을 별도로 설정해야 합니다.

### 실시간 개발

터미널 1:

```sh
npm start -- --port 8081
```

터미널 2:

```sh
npm run mac:dev
```

Android 네이티브 개발 앱을 먼저 빌드한 뒤 같은 개발 서버에 연결합니다. 화면 코드 저장 시 Fast Refresh가 적용됩니다. Mac의 SQLite와 LAN 서버를 수정하면 Mac 앱을 재시작해야 합니다. 웹만 확인하려면 `npm run web`을 사용합니다.

Expo Go에서는 사용할 수 있는 기능만 미리볼 수 있습니다. 자동 백그라운드 작업과 Android 네트워크 설정을 포함한 전체 검증에는 `android:native`로 만든 앱을 사용하세요.

### FatSecret 한국 음식 조회

한국 FatSecret 검색 페이지를 실제로 요청하고 HTML에서 음식 이름·브랜드·기준 제공량·칼로리·탄수화물·단백질·지방·상세 페이지 주소를 추출하는 개발용 서버가 있습니다. 브라우저는 이 로컬 서버의 JSON 결과를 받아 식단 입력 화면에 표시합니다.

`npm run web` 또는 `npm run dev`는 웹 화면(`localhost:8081`)과 음식 조회 서버(`127.0.0.1:8090`)를 함께 시작합니다. 웹 개발 명령을 종료하면 함께 시작한 조회 서버도 종료합니다. 이미 정상 실행 중인 조회 서버가 있으면 그대로 사용하며 종료하지 않습니다. 기존 웹 개발 명령을 사용 중이라면 한 번 종료하고 다시 실행하세요.

조회 서버만 따로 실행하려면 다음 명령을 사용합니다.

```sh
npm run food-search:dev
```

서버는 `127.0.0.1:8090`에서 실행됩니다. `GET /health`로 실행 상태를 확인하고, 아래처럼 검색할 수 있습니다.

같은 포트에서 음식 조회 서버가 이미 정상 실행 중이면 주소를 안내하고 중복 실행 명령은 종료됩니다. 기존 서버는 계속 사용할 수 있습니다. 서버 코드 수정 후에는 기존 서버를 실행한 터미널에서 `Ctrl+C`로 종료한 뒤 다시 실행하세요. 다른 프로그램이 포트를 사용하거나 기존 서버의 상태를 확인하지 못하면 오류와 포트 변경 방법을 표시합니다. `lsof -nP -iTCP:8090 -sTCP:LISTEN`으로 사용 중인 프로세스를 확인할 수 있습니다.

```sh
curl --get 'http://127.0.0.1:8090/foods/search' --data-urlencode 'q=닭가슴살'
```

검색 첫 페이지의 최대 10개를 JSON으로 반환합니다. `servingText`는 페이지에 표시된 영양값의 기준량이고, `servingGrams`는 `100g` 또는 `1인분 (110g)`처럼 무게가 명확할 때만 포함합니다. `100ml`나 `1개`의 무게를 추측하지 않습니다. 조회 결과는 자동으로 기록하거나 저장하지 않습니다.

검색 결과 없음은 빈 `foods` 배열로 반환합니다. 페이지 구조·영양값을 읽지 못한 경우는 조회 오류(502), 요청 시간 초과는 504, 잘못된 검색어는 400으로 구분합니다. 요청은 10초, HTML 응답은 1MB로 제한합니다. `localhost:8081`과 `127.0.0.1:8081` 개발 화면에서 사용할 수 있도록 CORS를 허용합니다. 다른 조회 포트가 필요하면 `FOOD_SEARCH_PORT=8092 npm run web`으로 실행하며 웹 화면에도 주소를 자동 전달합니다. 따로 띄운 웹 화면에서 조회 주소를 지정하려면 `EXPO_PUBLIC_FOOD_SEARCH_URL=http://127.0.0.1:8092`를 사용하세요.

## 두 기기 연결

1. Mac과 Android를 같은 집 Wi-Fi에 연결하고 두 앱을 엽니다.
2. Mac 화면 아래 **백업 및 기기 동기화 → 기기 연결**을 엽니다.
3. Android의 **기기 연결 → Mac QR 코드 스캔**으로 스캔합니다. 연결 코드를 직접 붙여 넣어도 됩니다.
4. 최초 연결 시 바로 동기화합니다. 이후 앱이 활성 상태이면 약 25초 간격으로 확인합니다.
5. 어느 앱에서든 **지금 동기화**를 누르면 즉시 동기화를 요청합니다. Mac 버튼은 실행 중인 Android 앱을 깨워 요청하고, 응답이 없으면 약 20초 뒤 안내합니다.

Mac은 TCP 47831 포트에서 수신합니다. macOS의 로컬 네트워크 권한과 방화벽 수신 연결을 허용해야 합니다. 게스트 Wi-Fi의 기기 격리, VPN, 회사 네트워크 정책은 연결을 막을 수 있습니다. Mac의 IP 주소가 바뀌면 새 QR 코드를 다시 스캔하세요. 자동 기기 검색(mDNS)은 아직 사용하지 않습니다.

연결 코드는 내 기록에 접근하는 비밀 키를 포함합니다. Android에서는 SecureStore, Mac에서는 OS 키 저장소로 암호화한 파일에 보관합니다. 전송 본문은 NaCl secretbox로 암호화·인증합니다. 서버는 브라우저 Origin 요청, 잘못된 키/데이터, 재전송된 요청, 5분 이상 오래된 요청을 거절합니다. 두 기기의 날짜·시간은 자동 설정을 사용하세요. 키가 노출됐거나 휴대폰을 바꾸면 Mac에서 **연결 키 재발급** 후 다시 연결합니다.

## 저장과 동기화 규칙

- 앱의 기본 데이터는 각 기기의 `exercise.sqlite`에 저장합니다. 기록별로 entries 테이블에 저장하며, 수정·삭제 이력과 기기 정보를 함께 보존합니다.
- Mac 데이터 폴더: `~/Library/Application Support/ExerciseTracker/`.
- Android 데이터: 앱 내부 SQLite 디렉터리. 연결 정보와 기록은 분리합니다.
- 서로 다른 식단·운동 항목을 합칩니다. 같은 날 입력한 서로 다른 항목도 유지합니다.
- 운동 카드는 하루의 운동 순서를 표시합니다. 새 운동은 마지막에 추가되며, 수정·재실행·백업 복원·동기화 후에도 순서를 유지합니다. 두 기기에서 같은 순서에 동시에 추가한 운동은 기록 ID 기준으로 일관되게 정렬합니다. 순서 정보가 없는 기존 설치 앱 기록은 현재 표시 순서를 기준으로 이어갑니다.
- 삭제는 삭제 이력을 남겨 오래 오프라인이던 기기에서 기록이 부활하지 않도록 합니다.
- 같은 항목을 양쪽에서 동시에 수정하면 더 큰 논리 버전이 우선합니다. 같으면 기기 ID의 고정 순서로 결정합니다. 실제 시각상 마지막 편집을 항상 의미하지 않으며, 충돌 선택 UI는 없습니다.
- Mac이 꺼져 있거나 절전 상태이면 각자 SQLite에 계속 기록하고 다음 연결에 합칩니다.
- 첫 연결도 기존 양쪽 기록을 합칩니다. 이름이 같아도 서로 별도로 입력한 항목은 서로 다른 기록입니다.
- 복원은 현재 기록 전체를 교체하는 로컬 편집으로 처리하며, 이 변경도 이후 동기화됩니다.

## 자동 JSON 백업

SQLite가 평소 사용하는 저장소이고 JSON은 복구·이동용 복사본입니다. 동기화는 백업 파일 생성 시점을 기다리지 않고 최신 기록과 변경 이력을 직접 교환합니다.

- 날짜별 파일: `운동관리-YYYY-MM-DD.json`.
- 그날 처음 백업을 실행할 때의 전체 기록을 하루 한 번 저장합니다. 이후 변경 때마다 같은 파일을 덮어쓰지 않습니다. 최신 상태가 필요하면 **백업 내보내기**를 사용하세요.
- Mac에서는 앱이 실행 중인 동안 매분 날짜를 확인합니다. 창을 닫아도 앱을 완전히 종료하지 않았다면 계속 동작합니다.
- Android에서는 앱 실행/복귀 및 실행 중 매분 확인합니다. 별도로 OS 백그라운드 작업을 최소 15분 간격으로 요청합니다. OS가 실행 시점을 결정하므로 정확한 시각이나 매일 실행을 보장하지 않습니다.
- 종료·절전·강제 종료 등으로 놓쳤다면 다음 실행 때 **그때의 현재 기록을 오늘 날짜로** 백업합니다. 지나간 날짜의 상태를 소급 생성하지 않습니다.
- Android 백그라운드 작업은 백업 후 Mac 연결도 시도합니다. Mac이 응답하지 않아도 로컬 백업은 남습니다.
- Mac: 데이터 폴더 아래 `backups/`. Android: 앱 문서 디렉터리 아래 `backups/`.
- **자동 백업 목록**에서 파일을 내보낼 수 있습니다. 최근 60개를 표시하며, 이전 파일도 삭제하지 않습니다.
- **백업 복원** 전에 별도의 `before-restore` 백업을 생성합니다. 보호 백업을 만들 수 없으면 복원을 중단합니다.

자동 백업도 같은 기기에 있으므로 앱 데이터 삭제·기기 고장으로 함께 사라질 수 있습니다. 보관할 백업은 외부 폴더나 다른 기기로 내보내세요. JSON 백업에는 기록만 포함하고 연결 키나 동기화 이력은 포함하지 않습니다. 파일은 10MB까지 가져올 수 있습니다.

## 기존 기록 이전

- **동일한 Android 앱 저장 영역**의 기존 `harugyeol.v1` AsyncStorage 데이터는 최초 실행 시 검증하고, `before-migration` JSON 백업을 만든 뒤 SQLite로 옮깁니다. 기존 원본은 지우지 않습니다. 읽기/검증/백업 실패 시 이전을 중단합니다.
- Expo Go와 독립 설치 앱은 저장 영역이 다릅니다. Expo Go에서 JSON을 내보내 독립 앱에서 복원하세요.
- 기존 브라우저 기록은 브라우저에서 **백업 내보내기 → Mac 앱에서 백업 복원**으로 옮깁니다. Mac 설치 앱은 브라우저의 localStorage에 직접 접근하지 않습니다.
- 기존 version 1 JSON 백업을 읽을 때 체중 값은 제외하고 식단·운동 기록만 가져옵니다. 기존 동기화 기록의 체중 항목도 제거합니다. 복원은 전체 교체이므로 양쪽에 기록이 있다면 먼저 백업하세요.
- 이전에 생성한 JSON 백업 파일과 AsyncStorage 원본은 자동으로 삭제하지 않으므로 체중 값이 남아 있을 수 있습니다.

## 검증

```sh
npm run check          # 포맷·린트·타입·테스트 전체 검증 (CI와 동일)
npm run lint           # oxlint 검사 (경고도 실패 처리)
npm run lint:fix       # 자동 수정 가능한 린트 문제 수정
npm run format        # Oxlint 안전 수정 후 Oxfmt로 코드·설정·문서 포맷팅
npm run format:check  # 파일 변경 없이 포맷 검사
npm run typecheck
npm test
npm run build          # 웹 자산
npm run build:android  # Android JS/자산 번들만 생성, APK 아님
npm run desktop:compile
```

Oxlint 설정은 `.oxlintrc.json`에서 관리합니다. 앱·Electron·스크립트·테스트의 JavaScript/TypeScript를 검사하며, React와 Vitest 규칙을 포함합니다. 빌드 결과물과 생성된 Android/iOS 프로젝트는 제외합니다. 타입 검사는 별도로 `npm run typecheck`를 실행하세요.

포맷팅은 Oxfmt가 담당하며 `.oxfmtrc.json`에서 설정합니다. 들여쓰기 2칸, 작은따옴표(JSX는 큰따옴표), 세미콜론, 줄 너비 100을 기준으로 사용합니다. import는 side-effect → Node 내장 → 외부 패키지 → 프로젝트 모듈 → 상대 경로 순으로 그룹화하되, 실행 순서에 영향을 주는 side-effect import 내부 순서는 유지합니다. `package.json` 키 순서도 유지하며, 빌드 결과물·생성된 네이티브 프로젝트·`package-lock.json`은 포맷팅에서 제외합니다.

Oxlint는 중괄호 생략, 중첩 삼항식, 명시적 `any`, 중복·자기 자신 import, 위험한 동적 코드 실행, React key·HTML 삽입, 잘못된 Hook 의존성과 `.only`·`.skip` 테스트도 검사합니다. 속성이 2개 이상인 객체의 줄바꿈과 type 선언 뒤 빈 줄도 자동 수정하며, `npm run format`과 VS Code 저장 시 Oxfmt보다 먼저 적용됩니다. 상세 기준과 변경 절차는 [개발 안내](CONTRIBUTING.md#자동-검사-기준)에 정리되어 있습니다.

VS Code에서는 프로젝트 추천 확장인 [Oxc](https://marketplace.visualstudio.com/items?itemName=oxc.oxc-vscode)를 설치하면 JavaScript/TypeScript, JSON, YAML, Markdown 파일을 저장할 때 자동 포맷팅합니다.

테스트는 날짜·기존 JSON 검증, SQLite 재시작 후 유지, 하루 1회 백업, 이전·복원 실패 시 보호, 동시 편집·삭제 병합, 실제 로컬 HTTP 암호화 통신, 재전송/외부 Origin 차단, 수동 동기화 응답을 검증합니다. LAN 테스트는 로컬 포트 바인딩이 가능한 환경에서 실행해야 합니다.

이번 구현 환경에서 Android Studio/SDK 및 연결 기기가 없어 Android APK 빌드와 실제 QR 스캔·파일 공유·백그라운드 실행은 검증하지 못했습니다. Android JS 번들 생성과 네이티브 설정 해석은 확인했습니다.

## 주요 파일

- `src/domain/`: 기록 데이터 형식·검증과 동기화 병합 규칙

- `src/infrastructure/`: Android SQLite·파일, 브라우저 저장소, Electron 브리지, LAN 통신
- `src/presentation/tracker/`: 기록 편집·날짜 선택 화면과 상태 관리
- `src/presentation/sync/`: 백업·기기 연결·동기화 화면
- `App.tsx`, `src/presentation/tracker/TrackerScreen.tsx`: 앱 진입점과 최상위 기록 화면
- `src/infrastructure/native-storage/`: Android SQLite, 백업 파일 및 엔진 어댑터
- `src/infrastructure/services.ts`, `background.ts`: Android LAN 클라이언트·백그라운드 작업
- `src/infrastructure/services.web.ts`, `platform.web.ts`: 브라우저 및 Electron 연결
- `desktop/storage.ts`: Mac SQLite 및 백업 파일
- `desktop/lan-server.ts`: 암호화된 LAN 통신 및 Android 응답 대기
- `desktop/main.ts`, `desktop/preload.cjs`: 격리된 Electron 창과 제한된 IPC
- `electron-builder.yml`: Mac 패키징
